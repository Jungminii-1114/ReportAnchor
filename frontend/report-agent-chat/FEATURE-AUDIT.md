# 미리보기와 실제 확장 기능 점검

2026-11-06 기준. 기존 4단계 버전은 변경하지 않았습니다.

| 기능 | 실제 확장 구현 가능 여부 | 현재 코드 상태 |
| --- | --- | --- |
| 사이드 패널 채팅, 질문·추천 질문, 평가 기준 입력 | 가능 | 구현됨 |
| 새 대화, 입력 초안·대화 저장 | 가능 | 구현됨. Chrome 세션 저장소 사용 |
| 대화 전체화면(새 탭), 패널 복귀 | 가능 | 구현됨. F11 전체화면은 아님 |
| 두 화면의 질문·기준·대화·생성 상태 연동 | 가능 | 구현됨 |
| PDF 크게 보기 | 가능 | 패널 내부 버튼에서 실제 chrome.sidePanel.close 호출 |
| 패널 다시 열기 | 가능 | Chrome 확장 아이콘의 기본 동작을 패널 열기로 설정 |
| 찾는 중 / 찾음 / 찾기 실패 표시 | 가능 | 화면 구현됨. 실제 PDF 탐색은 미구현 |
| 답변 생성·중단·후속 질문·충족 표시 | 가능 | 고정 예시 응답과 대기 타이머. 실제 AI 분석 및 요청 취소는 미구현 |
| 원문 인용 펼치기 | 가능 | 화면 구현됨. 인용 내용은 고정 예시 |
| 근거 페이지로 이동 | 대상 PDF 접근 방식에 맞춰 구현 필요 | 미리보기의 예시 PDF에서만 동작. 실제 확장에서는 안내 표시 |
| Chrome 주소창 옆의 글자형 전환 버튼 | 같은 형태로 임의 추가 불가 | 제거. 미리보기에는 실제 도구 모음에 대응하는 확장 아이콘 모형만 표시 |
| 왼쪽 PDF 뷰어 | Chrome 기본 뷰어 사용 | 미리보기에서만 예시 PDF를 표시. 실제 확장 내부에 PDF 뷰어를 넣지 않음 |

## 실행 및 검증

- Chrome 141 이상 필요: 패널 닫기 API 지원 버전에 맞춰 manifest 최소 버전을 변경했습니다.
- Chrome 156에서 확장을 설치해 패널 opened / closed 이벤트로 실제 열기·닫기·재열기를 확인했습니다.
- 확장 아이콘 클릭 시 패널 열기 설정을 확인했습니다. 자동화 검증의 재열기는 Chrome API로 수행했습니다.
- 작성 중 질문은 닫기 후 다시 열거나 화면을 다시 불러와도 유지됐습니다.
- 미리보기 초기 자동 찾는 중 → 찾음 → 2.5초 후 안내 숨김 확인.
- 320 / 380 / 1440px에서 미리보기 레이아웃과 버튼 확인.
- 대화 전체화면과 패널 사이 양방향 연동, 중단, 새 대화, 복귀를 별도 검증했습니다.

## 실제 문서 연결 시 필요한 작업

PDF URL/탭 식별, 파일 접근 권한, 파일 획득 및 파싱, 분석 API 호출, 응답·근거 페이지 매핑을 연결해야 합니다. 로그인 필요 문서, 로컬 파일, 임시 URL 또는 사이트 자체 PDF 뷰어는 접근 방식이 달라 모든 PDF를 동일하게 처리한다고 보장할 수 없습니다.
현재 검토는 UI와 확장 화면 제어의 구현 및 가능성 점검입니다. PDF/AI 백엔드 구현을 완료했다는 의미가 아닙니다.
