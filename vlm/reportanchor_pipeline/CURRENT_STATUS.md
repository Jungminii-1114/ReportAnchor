# 구현 상태와 남은 문제

선택 규칙은 `source-evidence-policy-revision-2`로 고정했습니다. 파이프라인의 구현 연결과 문서 내용의 정확도 검증은 별개입니다. 이 저장소 변경에는 실제 PDF의 내용, 응답 원문, 검증 산출물을 추가하지 않았습니다.

## 구현한 부분

- PDF 전체 기본 추출, Docling의 페이지별 추출과 원본 해시 기반 캐시 재사용.
- 고정된 Python 선택 규칙과 OCR/VLM 분기.
- 호출 횟수 제한, 중간 저장·재개, 실패 응답 보존.
- 원본과 보완 내용을 덮어쓰지 않는 결과 저장 및 RAG 후보 형식.

## 현재 한계

- VLM 요청의 `num_predict`가 4096으로 고정돼 있습니다. 추론 과정이 길면 최종 JSON이 나오기 전에 생성 길이 제한에 도달할 수 있습니다.
- `failed_pages`는 페이지 단계 오류만 나타냅니다. 실제 VLM 실패는 영역별 `vlm.status`와 `error`를 확인해야 합니다.
- JSON 형식 통과와 모델의 `issues`는 독립적인 내용 검증이 아닙니다.
- 원문 임의 수정·누락, 병합 셀의 열 범위 불일치가 발생할 수 있습니다.
- 추가 OCR 결과를 자동으로 VLM에 재전송하는 단계는 포함하지 않았습니다.
- RAG 청킹·인덱싱·사용 승인은 아직 연결하지 않았습니다.

## 다음 수정 사항

1. 추론·출력 설정을 조정하고 작은 대상부터 재검증.
2. 원문 보존, 셀 범위, 수치·단위·관계 검사 보완.
3. RAG 담당자와 청킹·승인 조건 합의.

실제 문서의 결과 자료는 별도 공유 경로에서 검토합니다.
