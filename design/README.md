## Material 3 기준

- 웹앱이므로 **Material 3**를 기준으로 하고, 문서 도구의 3열 구조는 HIG를 따릅니다.
- 8dp 그리드, M3 타입 스케일, 3px 탭 인디케이터, tonal surface, 상태 레이어를 사용합니다.
- 상태 색은 항상 텍스트 라벨과 함께 씁니다: `뒷받침` · `모순` · `근거 부족` · `일부 확인` · `답변 완료`.
- 서체: UI `Noto Sans KR`, 문서 `Noto Serif KR`, 메타 `JetBrains Mono`.
- 타입: 라벨 10–13, 본문 14/24, 제목 16, 질문 16, 지면 H1 24, 통계 32.
- 색 역할: primary `#1F6B54`, primaryContainer `#D5EBE0`, secondaryContainer `#E3F1EA`, tertiary `#9A5B00`, error `#B42318`, surface `#FFFDF8`, surfaceContainer `#F6F3EC`, surfaceContainerHigh `#F1EDE3`, surfaceContainerHighest `#EAE5D9`, desk `#EFEBE1`, outlineVariant `#E4DED1`.
- 상호작용: hover 8% · focus 12% · pressed 16% · disabled 38%, focus ring 2px + offset 2px.

## 검토 패널 — 대화 스레드

검토 패널은 보고서 요약 카드가 아니라 `앵커`와의 대화입니다. 사용자는 내부 노드가 아니라 결과를 받고, 필요할 때만 근거를 펼칩니다.

- 기본 순서: 사용자 질문 bubble → 앵커 상태 태그 → 답변 → 근거 한 줄 → inline callout(`모순`/`확인`) → 후속 질문 chip.
- 내부 구조(클레임 목록, 연결 자료, 노트)는 기본 화면에 두지 않습니다. `자세히 보기` 하나로만 펼칩니다.
- 상태는 점 + 텍스트로 표기합니다: `뒷받침` `모순` `근거 부족` `일부 확인` `답변 완료`. 색만으로 의미를 전달하지 않습니다.
- 상태 어휘는 두 층으로 나눕니다.
  - 클레임 단위: `뒷받침`(출처와 일치) · `모순`(출처 간 불일치) · `근거 부족`(자료에 수치·문장 없음).
  - 스레드 단위: `일부 확인`(답변은 완료, 일부 클레임 미확인 또는 모순) · `답변 완료`(모든 클레임 확인).
- `일부 확인`은 답변 진행률이 아니라 근거 검증 범위입니다. 스트리밍·중단으로 읽히지 않도록 `답변`이라는 단어를 쓰지 않습니다.
- 사용자 bubble은 우측 정렬 `#E3F1EA`, radius `16/16/4/16`. 앵커 답변은 컨테이너 없이 왼쪽 정렬 + 24px 아바타.
- callout은 error `#FBEAE7` · success `#E3F1EA`, radius 12. 빠른 답장 chip은 `#F6F3EC`, radius 12.
- 컴포저는 하단 고정. 처리 원리·프라이버시 설명 없이 placeholder와 전송 버튼만 둡니다.
- 스레드 안에 탭·섹션 제목·상태 카운트를 두지 않습니다.

## 탐색기 — 펼침 / 접힘

탐색기는 옵시디언 볼트처럼 사용자가 열고 닫는 고정 영역입니다. 두 상태는 같은 워크스페이스의 레이아웃 상태이며, 같은 셸과 검토 패널을 공유합니다.

| 상태 | 폭 | 구성 | 문서 영역 |
|---|---|---|---|
| 펼침 (기본) | 276 | 브랜드 · 검색 · 자료 트리 · 색인 footer | 728 |
| 접힘 | 56 | 브랜드 · 검색 · 자료(선택) · 노트 · 검토 기록 · 하단 토글 | 948 |

- 전환은 헤더 우측 패널 아이콘(접기)과 레일 하단 패널 아이콘(펼치기)이 담당합니다. 접은 상태는 워크스페이스에 유지합니다.
- 접힘에서도 검토 패널은 436px로 고정하고, 지면은 600px를 유지한 채 데스크 안에서 중앙 정렬합니다. 문서 영역만 728 → 948로 넓어집니다.
- 레일 버튼은 40×40, 아이콘 14–20. 선택된 `자료`만 primaryContainer(`#D5EBE0`)로 표시합니다.
- 트리 행은 32px로 통일합니다. 형제 파일은 열린 문서와 같은 아이콘·제목 열에 맞추고, 열림/선택 상태는 행 높이가 아니라 배경으로만 표시합니다.
- 접힘 상태에서는 색인 footer를 레일에 반복하지 않습니다. 상태 색은 텍스트 라벨 없이 쓰지 않기 때문입니다. 색인 진행은 펼친 탐색기 또는 우측 패널이 담당합니다.
- 레이아웃 상태는 `03 · Material 3`에, 답변 상태는 `05 · States`에 둡니다.

## 검토 대화 — 도킹 / 플로팅

우측 도킹 패널과 우측 하단 플로팅 런처를 같은 셸에서 비교합니다. 플로팅은 도킹 패널을 대체하는 결론이 아니라, 대화를 접었을 때 지면이 얼마나 넓어지는지 보는 비교 레이아웃입니다.

| 상태 | 형태 | 구성 | 지면 |
|---|---|---|---|
| 도킹 (기본) | 우측 패널 436 | 상단 `대화` 탭 · 질문/답변 스레드 · 하단 컴포저 | 문서 영역 728 · 지면 600 |
| 플로팅 닫힘 | FAB 56×56 | 우측 하단 앵커 버튼 · 24 inset | 문서 영역 1164 · 지면 600 중앙 |
| 플로팅 패널 메뉴 | FAB 56×56 + 카드 300×292 | 5개 패널 목록 · `검토 대화` `일부 확인` · 현재 항목 `#FFFDF8` · `×` 닫기 | 지면 위 오버레이 |
| 플로팅 미리보기 | FAB 56×56 + 카드 300×232 | 상태 `일부 확인` · 최근 질문 · 답변 2줄 · 근거 `p.42 · p.23` · `대화 이어가기` | 지면 위 오버레이 |

### 패널 메뉴 / 미리보기

- 패널 메뉴(04)는 FAB에 hover하면 5개 패널 목록을 엽니다. 닫힘 상태의 `검토 대화` 단일 라벨을 메뉴로 확장한 형태입니다.
- 목록: `검토 대화` · `관계 그래프` · `자료 통계` · `검토 기록` · `설정`. M3 FAB menu의 2–6개 범위 안에서 최상위 패널만 담습니다.
- `검토 대화`는 `일부 확인` 상태를 점 + 텍스트로 표시하고, 선택하면 미리보기(05)로 이어집니다. 나머지 패널은 각 패널의 첫 화면으로 직접 엽니다.
- 메뉴는 hover로 열리지만 hover 이탈로 닫지 않습니다. `×`, 바깥 클릭, Esc로 닫습니다. 터치·키보드에서는 클릭/Enter로 엽니다.
- 미리보기(05)는 최근 질문 → 답변 2줄 → 근거를 먼저 보여주고 `대화 이어가기` 하나만 primary로 둡니다. `검토 기록`·`새 질문`은 패널의 `⋯` 메뉴로 보냅니다.
- 권장 흐름: 닫힘 FAB → hover 시 패널 메뉴 → `검토 대화` 선택 시 미리보기 → `대화 이어가기`로 도킹 패널 복귀. 그래프·통계·설정은 패널이 준비되면 메뉴에서 바로 해당 패널로 이동합니다.
- 메뉴 카드는 외곽선·그림자 없이 surfaceContainer `#F6F3EC`, 현재 항목은 `#FFFDF8`의 톤 차이로 구분합니다. 카드 오른쪽 끝은 1416, FAB 위 16px에 둡니다.
- 상태는 `일부 확인`처럼 점과 텍스트 라벨을 함께 씁니다. 메뉴에서도 색만으로 상태를 전달하지 않습니다.
- 레거시 패널 모드(`근거 대조`, `기준 검증`, `노트`)는 이번 핸드오프의 메뉴에 넣지 않습니다. 최상위 메뉴가 6개를 넘지 않게 하기 위한 결정이며, 필요하면 후속 버전에서 검토 대화의 하위 그룹으로 추가합니다.
- 플로팅에서도 지면은 600px를 유지하고, 패널이 쓰던 436px은 데스크 여백으로 돌려줍니다.
- 대화 내용과 상태 토큰은 도킹 패널과 같습니다. 차이는 위치와 열림 방식뿐입니다.

### 문서 작업 메뉴

- 하단 FAB가 패널 전환을 맡으므로, 문서 탭 바 오른쪽 `...`는 문서·PDF 작업 전용으로 분리합니다.
- 메뉴: `인쇄` · `PDF로 내보내기` · `페이지 설정` · `문서 정보`. 카드 220×228, 탭 바 아래 8px, 오른쪽은 탭 바 안쪽 16px에 맞춥니다.
- 검토 패널의 `⋯`는 대화 작업과 대화 공유·내보내기를 맡습니다. 문서 PDF 작업과 섞지 않습니다.

### 대화 작업 메뉴

- 검토 패널 헤더 오른쪽 `⋯`는 대화 자체에 대한 작업만 담습니다. 문서 작업은 탭 바 `...`, 패널 전환은 하단 FAB 메뉴가 맡습니다.
- 항목: `검토 기록` · `새 질문` · `공유` · `대화 내보내기`. 카드 220×244, 헤더 아래 8px, 패널 안쪽 24px에 맞춥니다.
- 앞 두 개는 대화 세션 작업, 뒤 두 개는 대화 내용 공유·내보내기입니다. 8px 그룹 간격으로만 나누고 구분선은 두지 않습니다.
- `공유`는 대화 링크·읽기 전용 공유, `대화 내보내기`는 스레드를 Markdown·PDF로 내보내는 진입점입니다. 실제 다이얼로그는 후속입니다.
- `⋯` 재클릭, 바깥 클릭, Esc로 닫습니다. `⋯`는 클릭으로 열고, 키보드에서는 Enter/Space로 엽니다.

## 톤 분리 원칙

YouTube·Pixel OS처럼 장식적 윤곽선 대신 표면 톤으로 영역을 나눕니다.

- 장식적 1px 구분선과 컨테이너 외곽선을 두지 않습니다.
- 영역 톤: 상단 밴드 `#F6F3EC` · 사이드바 `#EAE5D9` · 데스크 `#EFEBE1` · 지면/패널 `#FFFDF8`.
- 지면은 테두리나 그림자 없이 데스크와의 톤 차이로만 뜹니다.
- 칩·입력·보조 버튼은 외곽선 대신 tonal fill(`#F6F3EC` / `#F1EDE3` / container 색)을 씁니다.
- 기능적 선은 유지합니다: 포커스 링 2px · 탭 인디케이터 3px · 아이콘 스트로크.
- 표면 단계: `surface` → `surfaceContainerLow` → `surfaceContainer` → `surfaceContainerHigh` → `surfaceContainerHighest`.

## 문구 원칙

- 기술적 작동 원리와 프라이버시 설명을 UI에 쓰지 않습니다. (`기기 내 처리`, `외부 전송 없음`, `텍스트 추출`, `검색 가능한 색인 생성` 등)

- 대화 말풍선은 결과와 후속 행동만 담습니다. 내부 처리 과정은 노출하지 않습니다.

## 중복 정리 원칙

- 문서명은 **열린 탭**과 **탐색기 문서 행** 두 곳만 허용합니다.
- 페이지 위치와 줌은 **리더 바** 한 곳만 허용합니다.
- 사이드바에 가상 루트 행을 두지 않습니다. `자료`가 최상위입니다.
- 우측 패널은 탭·섹션 제목 없이 하나의 대화 스레드입니다. 역할은 말풍선과 상태 태그가 담당합니다.
- 플로팅 패널 메뉴는 최상위 패널 5개만 담습니다. 레거시 모드와 보조 동작은 최상위 메뉴에 넣지 않습니다.
- 문서 작업은 탭 바 `...`, 패널 전환은 하단 FAB 메뉴, 대화 작업·공유·내보내기는 검토 패널 `⋯`로 분리합니다. 같은 동작을 두 곳에 두지 않습니다.
- PDF 작업 메뉴는 `인쇄`·`PDF로 내보내기`·`페이지 설정`·`문서 정보` 네 개만 담습니다.
- 대화 메뉴는 `검토 기록`·`새 질문`·`공유`·`대화 내보내기` 네 개만 담습니다. 대화 내보내기는 스레드 단위이고, 문서 PDF 내보내기와 다른 동작입니다.
- 플로팅 미리보기는 최근 질문·답변 2줄·근거 한 줄만 담습니다. `자세히 보기`와 전체 스레드는 패널이 담당합니다.
- 클레임·연결 자료·노트는 기본 화면에 두지 않고 `자세히 보기` 뒤에만 둡니다.
- 색인 진행은 우측 패널 한 곳에서만 보여줍니다. 문서 영역은 skeleton, 사이드바는 상태 요약만 담당합니다.
- 같은 수치를 두 곳에 쓰면 역할을 라벨로 구분합니다. `색인 108쪽` vs `p.42 / 128`.
