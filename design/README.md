## Material 3 기준

- 웹앱이므로 **Material 3**를 기준으로 하고, 문서 도구의 3열 구조는 HIG를 따릅니다.
- 8dp 그리드, M3 타입 스케일, 3px 탭 인디케이터, tonal surface, 상태 레이어를 사용합니다.
- 상태 색은 항상 텍스트 라벨과 함께 씁니다: `뒷받침` · `모순` · `근거 부족` · `부분 답변` · `답변 완료`.
- 서체: UI `Noto Sans KR`, 문서 `Noto Serif KR`, 메타 `JetBrains Mono`.
- 타입: 라벨 10–13, 본문 14/24, 제목 16, 질문 16, 지면 H1 24, 통계 32.
- 색 역할: primary `#1F6B54`, primaryContainer `#D5EBE0`, secondaryContainer `#E3F1EA`, tertiary `#9A5B00`, error `#B42318`, surface `#FFFDF8`, surfaceContainer `#F6F3EC`, surfaceContainerHigh `#F1EDE3`, surfaceContainerHighest `#EAE5D9`, desk `#EFEBE1`, outlineVariant `#E4DED1`.
- 상호작용: hover 8% · focus 12% · pressed 16% · disabled 38%, focus ring 2px + offset 2px.

## 검토 패널 — 대화 스레드

검토 패널은 보고서 요약 카드가 아니라 `앵커`와의 대화입니다. 사용자는 내부 노드가 아니라 결과를 받고, 필요할 때만 근거를 펼칩니다.

- 기본 순서: 사용자 질문 bubble → 앵커 상태 태그 → 답변 → 근거 한 줄 → inline callout(`모순`/`확인`) → 후속 질문 chip.
- 내부 구조(클레임 목록, 연결 자료, 노트)는 기본 화면에 두지 않습니다. `자세히 보기` 하나로만 펼칩니다.
- 상태는 점 + 텍스트로 표기합니다: `뒷받침` `모순` `근거 부족` `부분 답변` `답변 완료`. 색만으로 의미를 전달하지 않습니다.
- 사용자 bubble은 우측 정렬 `#E3F1EA`, radius `16/16/4/16`. 앵커 답변은 컨테이너 없이 왼쪽 정렬 + 24px 아바타.
- callout은 error `#FBEAE7` · success `#E3F1EA`, radius 12. 빠른 답장 chip은 `#F6F3EC`, radius 12.
- 컴포저는 하단 고정. 처리 원리·프라이버시 설명 없이 placeholder와 전송 버튼만 둡니다.
- 스레드 안에 탭·섹션 제목·상태 카운트를 두지 않습니다.

## 탐색기 — 펼침 / 접힘

탐색기는 옵시디언 볼트처럼 사용자가 열고 닫는 고정 영역입니다. 두 상태는 같은 워크스페이스의 레이아웃 상태이며, 같은 셸과 검토 패널을 공유합니다.

| 상태 | 폭 | 구성 | 문서 영역 |
|---|---|---|---|
| 펼침 (기본) | 276 | 브랜드 · 검색 · 자료 트리 · 색인 footer | 728 |
| 접힘 | 56 | 브랜드 · 검색 · 자료(선택) · 노트 · 검토 기록 · 하단 토글 | 948 |

- 전환은 헤더 우측 패널 아이콘(접기)과 레일 하단 패널 아이콘(펼치기)이 담당합니다. 접은 상태는 워크스페이스에 유지합니다.
- 접힘에서도 검토 패널은 436px로 고정하고, 지면은 600px를 유지한 채 데스크 안에서 중앙 정렬합니다. 문서 영역만 728 → 948로 넓어집니다.
- 레일 버튼은 40×40, 아이콘 14–20. 선택된 `자료`만 primaryContainer(`#D5EBE0`)로 표시합니다.
- 트리 행은 32px로 통일합니다. 형제 파일은 열린 문서와 같은 아이콘·제목 열에 맞추고, 열림/선택 상태는 행 높이가 아니라 배경으로만 표시합니다.
- 접힘 상태에서는 색인 footer를 레일에 반복하지 않습니다. 상태 색은 텍스트 라벨 없이 쓰지 않기 때문입니다. 색인 진행은 펼친 탐색기 또는 우측 패널이 담당합니다.
- 레이아웃 상태는 `03 · Material 3`에, 답변 상태는 `05 · States`에 둡니다.

## 톤 분리 원칙

YouTube·Pixel OS처럼 장식적 윤곽선 대신 표면 톤으로 영역을 나눕니다.

- 장식적 1px 구분선과 컨테이너 외곽선을 두지 않습니다.
- 영역 톤: 상단 밴드 `#F6F3EC` · 사이드바 `#EAE5D9` · 데스크 `#EFEBE1` · 지면/패널 `#FFFDF8`.
- 지면은 테두리나 그림자 없이 데스크와의 톤 차이로만 뜹니다.
- 칩·입력·보조 버튼은 외곽선 대신 tonal fill(`#F6F3EC` / `#F1EDE3` / container 색)을 씁니다.
- 기능적 선은 유지합니다: 포커스 링 2px · 탭 인디케이터 3px · 아이콘 스트로크.
- 표면 단계: `surface` → `surfaceContainerLow` → `surfaceContainer` → `surfaceContainerHigh` → `surfaceContainerHighest`.

## 문구 원칙

- 기술적 작동 원리와 프라이버시 설명을 UI에 쓰지 않습니다. (`기기 내 처리`, `외부 전송 없음`, `텍스트 추출`, `검색 가능한 색인 생성` 등)
- 설명이 필요한 자리는 문구로 채우지 않고 비워 둡니다. 상태 라벨과 실제 데이터만 남깁니다.
- 대화 말풍선은 결과와 후속 행동만 담습니다. 내부 처리 과정은 노출하지 않습니다.

## 중복 정리 원칙

- 문서명은 **열린 탭**과 **탐색기 문서 행** 두 곳만 허용합니다.
- 페이지 위치와 줌은 **리더 바** 한 곳만 허용합니다.
- 사이드바에 가상 루트 행을 두지 않습니다. `자료`가 최상위입니다.
- 우측 패널은 탭·섹션 제목 없이 하나의 대화 스레드입니다. 역할은 말풍선과 상태 태그가 담당합니다.
- 클레임·연결 자료·노트는 기본 화면에 두지 않고 `자세히 보기` 뒤에만 둡니다.
- 색인 진행은 우측 패널 한 곳에서만 보여줍니다. 문서 영역은 skeleton, 사이드바는 상태 요약만 담당합니다.
- 같은 수치를 두 곳에 쓰면 역할을 라벨로 구분합니다. `색인 108쪽` vs `p.42 / 128`.

## 핸드오프 범위

- 포함: 기본 워크스페이스, M3 토큰, 컴포넌트 보드, 대화형 검토 패널, 근거 부족/색인/완료 흐름, 탐색기 펼침/접힘, 사이드바·리더·컴포저.
- 포함하지 않음: 기준 검증(T-02) 전용 화면, 다중 문서 비교, 모바일/좁은 폭 레이아웃, 실제 모션 스펙.
- 기준 검증 화면은 같은 셸에서 우측 패널만 기준 결과로 바꾸는 방향을 전제로 합니다.
- 검토 패널의 상태 태그·callout·`자세히 보기`·빠른 답장은 메인/상태/컴포넌트 보드에서 같은 토큰을 씁니다.

## 레거시

- 현재 핸드오프에 쓰지 않는 페이지·프레임은 이름 앞에 `LEGACY ·`를 붙입니다. 대상: 01 Foundation, 02 Structure v3, 03의 `LEGACY · Before — current (v3)`.
- `03 · Material 3`, `04 · M3 System`, `05 · States`는 현재 기준이므로 접두사를 붙이지 않습니다.
- `legacy/panel-modes/` — 우측 패널 확장 모드 보드와 4개 패널, 내보내기 이미지
  - `근거 대조`, `기준 검증`, `노트`, `검토 기록`
  - 2026-11-04 기준 메인 범위에서 제외. 삭제하지 않고 보관만 합니다.
- v6 스냅샷에는 이전 탭형 검토 인스펙터(`답변/클레임/연결`)와 섹션형 클레임/연결/노트가 남아 있습니다. 비교용으로만 봅니다.

## 규칙

1. 작업은 루트의 `reportanchor-workspace.figcraft`에서만 합니다.
2. 구조 변경이 승인될 때마다 `versions/`에 `reportanchor-workspace_vN_YYYY-MM-DD.figcraft`로 스냅샷을 남깁니다.
3. `versions/`와 `legacy/` 안의 파일은 수정하지 않습니다.
4. 더 이상 쓰지 않는 산출물은 삭제하지 않고 `legacy/<기능>/`으로 옮깁니다.
5. Git 커밋은 전체 이력을, `versions/` 스냅샷은 리뷰 가능한 마일스톤을 담당합니다.
