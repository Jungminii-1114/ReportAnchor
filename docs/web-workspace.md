# 로컬 자료함·원문 대조·T-01 웹 실행

## 시작하기

프로젝트 루트에서 다음을 실행한다. 검색·LangGraph 의존성은 requirements-rag.txt를 사용하며 PDF 추출·미리보기에는 PyMuPDF가 필요하다. 기존 프로젝트 .venv의 PyMuPDF도 자동으로 찾는다.

```bash
python -m pip install -r requirements-rag.txt
python scripts/run_rag_demo.py
```

기본 주소는 http://127.0.0.1:8765 이다. 현재 KISTEP blocks/chunks/PDF가 있으면 기본 자료로 연결하고, 없으면 빈 자료함으로 시작한다. 기본 자료 없이 시작하려면 --empty를 사용한다. PyMuPDF 환경을 별도로 지정할 때는 --pdf-python /경로/python 옵션을 사용한다. 필요한 데이터 파일이나 환경이 없는 새 체크아웃에서도 업로드 자료함으로 시작할 수 있다.

모델 없이도 자료 추가·관리·검색·PDF 페이지 보기를 사용할 수 있다. 왼쪽 **모델 설정**에서 설치한 Ollama 모델명을 적용한 뒤 **질의·검증** 모드로 질문한다. 모델 설정을 저장하는 것만으로 모델이 호출되지는 않는다. 실제 Ollama 서버가 실행 중이고 해당 모델이 준비되어 있어야 한다. 기존 --model, --provider, --timeout 옵션도 사용할 수 있다.

## 화면과 동작

- **왼쪽 자료함:** PDF 추가, 파일 끌어놓기, 자료 이름 검색, 검색 범위 체크, 이름 변경, 목록 제외·복원이다.
- **가운데 원문:** 검색 전에도 PDF 페이지를 넘겨 볼 수 있다. 답변·검색의 근거를 누르면 해당 문서·페이지·참조 블록을 표시한다. 추출 텍스트와 출처·버전·실행 JSON도 확인할 수 있다.
- **오른쪽 질문:** 질의·검증은 T-01 전체 흐름이며, 검색만 모드는 모델을 호출하지 않는다. 질문마다 독립 실행한다. 이전 대화를 자동으로 검색어에 합치지 않는다.
- 확인된 주장과 미확인 항목을 분리한다. 모순 주장은 한 번만 보정·재검증하며 검증을 통과하지 못한 문장을 확인된 답변으로 표시하지 않는다. 원문 기준 모델 판정이며 정확도 보증은 아니다.
- JSON 저장에는 최종 WorkflowResult와 실제 실행한 노드의 반환 블록을 포함한다. 원문·초안이 담긴 개발 검수용 자료이므로 공개용 배포 파일과 구분해 관리한다.

## PDF 업로드 범위

업로드는 파일당 30MB·300페이지 이하의 암호가 없는 PDF를 지원한다. 기존 pdf_extract.extract_pdf → rag_data.prepare_dataset → BM25 색인으로 연결하며 manifest.json, pages.jsonl, blocks.jsonl, chunks.jsonl과 chunking_report.json을 로컬 자료함에 보존한다. 업로드한 파일의 SHA-256과 추출 버전을 대조한다.

현재는 native text 기반이다. 스캔·사진만 있는 PDF는 텍스트가 없다는 안내로 종료하며 자동 OCR·VLM·HWP 처리를 수행하지 않는다. 일부 페이지만 텍스트가 없는 문서는 검색 가능한 부분을 색인하고 목록 메타데이터의 no_native_text_pages에 해당 페이지를 남긴다. 원본 PDF는 전체 페이지를 볼 수 있다.

동일 파일을 다시 추가하면 중복 색인 대신 기존 자료를 재사용하고, 제외되어 있었다면 복원한다. 사용자가 입력한 파일 이름은 표시 이름에만 사용하고 저장 경로에는 서버가 만든 식별자를 사용한다.

## 저장과 관리

기본 저장 위치는 프로젝트의 data/local_workspace/이다. --library-dir 옵션으로 변경할 수 있다. catalog.json은 표시 이름과 포함 상태를 보존한다. 업로드 자료와 추출·청킹 결과는 이 디렉터리 아래에 저장하며 Git에서 제외한다. 기본 연결 문서의 원본·기존 실험 결과는 변경하지 않는다.

**자료함에서 제외는 원본 삭제가 아니다.** 목록에서 숨기고 검색 대상에서 제외하며, 제외한 자료 보기에서 복원할 수 있다. 제외한 자료는 서버에서도 검색·검토 입력으로 거부한다. 질문·검토 작업의 상태와 결과는 현재 서버 메모리의 제한된 작업 목록에만 남는다. 서버 재시작 후 문서는 유지되지만 질문 작업은 복원되지 않는다.

## 실행·모델 경계

T-01은 선택한 자료만 묶어 검색한다. 브라우저가 보낸 임의 원문·문서 경로는 입력으로 받지 않는다. 검색·원문 조회는 한 번이며 모순 주장만 한 번 보정한다. 동일 요청 ID로 같은 작업을 다시 전송하면 진행 중이거나 완료된 작업을 재사용한다.

로컬 모델 기본 주소는 http://localhost:11434 이다. Cloud 모드는 서버의 OLLAMA_API_KEY를 사용하며 키를 브라우저나 반환 JSON에 넣지 않는다. Cloud를 선택하면 질문·선택 근거·주장이 외부 Ollama Cloud로 전송된다. 서버는 127.0.0.1에 바인딩하며 Host·Origin 검사와 요청 크기 제한을 적용한다. 사내 서비스 수준의 인증·접근 제어·악성 PDF 격리는 구현 범위 밖이다.

## 모델 응답 형식 오류

`INVALID_DRAFT_RESPONSE`는 N-04 모델 응답의 JSON 형식·필수 필드·근거 참조 검사가 실패했다는 뜻이다. `INVALID_VERIFICATION_RESPONSE`는 N-03 판정 응답 검사가 실패했다는 뜻이다. 모델이 응답한 경우에도 발생하므로 연결 오류와 구분한다.

로컬 Ollama에는 노드별 JSON Schema를 요청한다. 생성 지시와 입력 자료를 system/user 메시지로 분리하고, 생성·검증 입력에는 원문과 식별 정보를 중심으로 전달한다. 반복되는 블록 좌표는 모델 입력에서 제외하지만 EvidenceBundle과 최종 출처의 원문 위치·문서 버전은 유지한다. 응답 스키마를 사용해도 노드의 ID·근거 참조 검사를 생략하지 않는다. JSON 형식 보장은 내용의 사실성 보장이 아니다.

코드를 업데이트했다면 웹 서버를 실행한 터미널에서 Ctrl+C로 종료한 뒤 프로젝트 루트에서 다시 실행한다. Ollama 서버는 계속 실행해도 된다.

```bash
python scripts/run_rag_demo.py --model "qwen3:8b"
```

브라우저를 새로고침하고 질문을 다시 보낸다. 서버 재시작 전의 작업 결과가 새 코드로 자동 재실행되지는 않는다. 처음에는 “2025년 경상운영비는 얼마인가?”처럼 특정 항목을 질문한다. 문서 전체 요약을 요청해도 현재 T-01은 검색된 일부 근거만 사용하므로 전체 문서 요약과 구분해야 한다.

Ollama Cloud에는 현재 지원하지 않는 `format` 필드를 보내지 않으며 프롬프트와 엄격한 응답 검사로 처리한다. 지원 범위는 [Ollama 구조화 출력 문서](https://docs.ollama.com/capabilities/structured-outputs)를 따른다.

## API

| API | 용도 |
| --- | --- |
| GET /api/documents | 활성·제외 자료 목록, 모델·업로드 설정 |
| POST /api/documents/upload?filename=... | PDF 바이트 전송, 비동기 작업 반환 |
| POST /api/documents/update | document_id와 title 또는 active 변경 |
| GET /api/info?document_id=... | 선택 자료 메타데이터 |
| GET /api/preview?document_id=...&page=... | PDF 이미지, 선택형 chunk_id·highlight |
| POST /api/model | model·provider 적용, 모델 호출 없음 |
| POST /api/search | query·top_k·document_ids로 검색만 실행 |
| POST /api/qa | query·top_k·document_ids·request_ref로 T-01 작업 생성 |
| GET /api/jobs?id=... | 업로드·검토 작업 상태 및 완료 결과 |

## 검증 범위

자동 검사는 실제 PDF의 업로드·추출·청킹·색인·원문 미리보기·문서 범위·자료함 재시작 보존과 T-01 계약을 확인한다. 모델 응답은 모의로 제공하며 실제 모델 판정 정확도를 측정하는 실험은 아니다. 검수 화면에서 모의 서버를 사용할 때에는 TEST · MOCK MODEL과 모의 응답 안내를 명시한다. 일반 실행 명령에는 모의 모델이 포함되지 않는다.
