# ReportAnchor 설계·구현 핵심 정리

> 기준: 2026-11-12 · JM 구현 / JS 설계 `ad430ab` 참고

## 1. 프로젝트 목표와 구조

기업·공공기관의 보고서 검토자가 PDF에서 필요한 근거를 찾고, 질문의 답변과 명시한 기준의 충족 여부를 원문과 함께 확인하는 로컬 문서 검토 Agent이다. 최종 의사결정은 사용자가 수행한다.

전체 설계는 **N-10 요청 확인·라우팅 → 목적별 Tool 하나 → N-11 결과 전달**이다. 현재 JM은 RAG와 T-01·T-02를 구현한 단계이며, N-10/N-11·메인 하네스는 별도 통합 대상이다.

## 2. 데이터와 공통 기반

```text
PDF → PyMuPDF 텍스트 추출 → 검증·청킹 → Kiwi 토큰화·BM25 검색
    → 원문 문맥 보강 → 답변/기준 판정 → 근거 검증 → 구조화된 결과
```

| 데이터 | 목적 |
| --- | --- |
| `manifest.json` | 문서 ID·원본 해시·페이지 수 등 문서 단위 정보 |
| `pages.jsonl` | 페이지별 추출 텍스트·메타데이터 |
| `blocks.jsonl` | 원문 블록·페이지·좌표 등 출처 복원 기반 |
| `chunks.jsonl` | 검색 단위 텍스트와 원본 블록·문자 구간 연결 |

현재 입력은 PyMuPDF native text 데모이다. 최종 Parser/VLM 출력 어댑터와 OCR·HWP·표 구조 해석은 완료 범위에 포함하지 않는다. 검색기는 BM25 기준선이다.

## 3. 구현한 노드와 Tool

| 노드 | 책임 |
| --- | --- |
| N-01 `retrieve_evidence` | 문서·버전 범위를 제한한 근거 후보 검색 |
| N-02 `get_source_context` | 원문 복원·주변 문맥 보강·출처 연결 |
| N-03 `verify_grounding` | 주장·판정과 원문 근거의 정합성 검증 |
| N-04 `draft_answer` | 근거 기반 답변 초안 생성·지정 주장 보정 |
| N-05 `structure_criteria` | 사용자 기준 원문을 보존하며 평면 AND/OR 조건으로 구조화 |
| N-06 `evaluate_criterion` | 조건별 충족·미충족·확인 불가 판정 제안 |

- **T-01 Document QA:** `N-01 → N-02 → N-04 → N-03`. 모순 주장만 최대 1회 보정·재검증한다. 검색은 반복하지 않는다. 확인된 주장과 미확인 항목을 분리한다.
- **T-02 Criteria Review:** `N-05 → 기준별 N-01/N-02/N-06 → N-03 → 집계`. 검증 후 조건별 결과로 AND/OR를 계산한다. 일부 미지원 기준의 원문·사유도 보존하며 전체 합격·총점은 임의로 만들지 않는다.
- **T-03 Comparative Analysis:** 문서·기간·지표 비교를 위한 설계 단계이며 아직 구현하지 않았다.

T-01은 로컬 웹·Python·CLI, T-02는 Python·CLI에서 실행한다. 웹은 PDF 업로드·자료 선택·이름 변경·제외/복원·원문 대조를 제공한다. 기존 웹의 질의·검증 모드는 T-01이다.

## 4. 핵심 설계 원칙

- **실행 상태와 업무 판정 분리:** 처리 실패와 기준 미충족은 다르다. 검색에서 못 찾은 것만으로 문서 내 정보 부재를 확정하지 않는다.
- **출처·ID 보존:** 문서 버전·블록·문자 구간·좌표를 유지하고 주장 ID를 코드에서 발급한다. 기준별 근거를 섞지 않는다.
- **기준과 인용의 임의 생성 방지:** 미지원 중첩 논리를 단순화하지 않는다. N-06은 제공된 원문 구간 ID를 선택하고 실제 인용문은 코드가 복원한다.
- **공통 통신, 노드별 책임:** OllamaClient는 API 통신·설정을 담당하고 노드는 프롬프트·파싱·참조 검사를 담당한다. 로컬 호출에 JSON 스키마와 컨텍스트 크기 16,384를 명시한다.
- **로컬 우선:** 선택형 Ollama Cloud 사용 시 질문·선택 근거 등이 외부 전송된다. 로컬 실행 자체가 기업 수준의 보안 검증 완료를 뜻하지는 않는다.

## 5. 확인한 결과

- **자동 검사:** RAG·웹 267개와 별도 PyMuPDF 환경의 PDF 검사 9개 통과이다. 자동 검사에는 모의 모델 응답을 사용한다.
- **실제 데이터:** 공개 KISTEP 문서 117페이지·블록 3,105개·청크 180개를 연결하였다.
- **실제 모델:** 로컬 `qwen3:8b`로 2025년 경상운영비 4,566백만원을 검토하였다. ‘4,000백만원 이상’은 충족, ‘5,000백만원 이상’은 미충족이며 두 판정 모두 N-03 검증을 통과하였다.
- **수정한 실패:** 모델의 인용문 재작성은 원문 구간 ID 선택으로 대체하였다. 서버가 입력을 잘라 처리하는 현상은 명시적 컨텍스트 설정으로 해결하고 마지막 실제 실행 로그에서 잘림이 없음을 확인하였다.

위 결과는 구현·연결 및 제한된 사례의 확인이다. 일반적인 검색·생성·판정 정확도 평가와 구분한다.
