## 항목별 상세

### 1. [계약 추가] 표 청크의 제목·행/열 헤더·단위 사전 보존 및 전달
- **문제:** 원문 조회 노드(`N-02`)는 MVP에서 *앞뒤 고정 길이 문자 확장*만 수행한다. 그러나 기준 판정 노드(`N-06`)에 Python [`Decimal`](https://docs.python.org/3/library/decimal.html) 수치 비교 계산기를 도입하기로 확정하면서, 행이 많은 표의 중간 청크가 검색되면 앞뒤 고정 길이만으로는 표 상단의 단위 표기(`단위: 백만원`)나 병합 열 헤더(`2025년 / 연결`)가 문맥에서 잘려 나가는 문제가 생긴다.
- **계약 추가 이유:** 원문 조회 노드에 복잡한 실행 시점 표 구조 탐색을 억지로 추가하지 않으면서도, 정량 판정이 단위·헤더 부재로 대량 `확인 불가`가 되거나 잘못된 열을 비교하는 실패를 막기 위함이다.
- **확정된 계약:**
  1. **파싱·청킹 단계:** 표에서 생성된 청크마다 **표 제목 · 행/열 헤더 경로 · 단위 표기(및 가능한 각주 참조)**를 청크 메타데이터(`table_context` 등)에 함께 보존한다.
  2. **원문 조회 노드(`N-02`):** 실행 시점에 표 구조를 임의로 추측해 채우지 않고, **파싱·청킹 단계에서 사전 보존된 표 헤더·단위 메타데이터를 `EvidenceBundle`의 해당 근거 항목에 그대로 전달**한다.
  3. **기준 판정 노드(`N-06`):** 정량 추출 시 본문 문맥과 함께 전달된 표 헤더·단위 메타데이터를 사용해 `raw_unit`, `period`, 대상 범위를 채운다.

### 2. [백로그 · 테스트] 근거 검증 노드의 동일 모델 자기편향 검증 및 JEV류 선택 모델 검토
- **문제:** 동일 기반 모델(`deepseek-v4.1-flash`)로 생성(답변 초안·기준 판정)과 검증(근거 검증)을 둘 다 돌리면, 세션을 분리해도 모델이 자체 생성 문체를 선호해 틀린 주장을 `supported`로 통과시킬 위험이 있다.
- **대응:** 평가셋 구축 후 **거짓 통과율(False Positive Rate)**을 별도 측정하는 테스트를 백로그에 등록한다. 편향이 기준치를 넘으면 **JEV류 선택형 검증 모델/라우팅**(예: 이종 모델 검증기 또는 위험도 기반 라우팅) 도입을 검토한다.

### 3. [백로그] 기준 판정 노드의 정량 추출·근거 연결 오류 집중 대응
- **문제:** 문헌 오류 분석([*TAT-QA*](https://aclanthology.org/2021.acl-long.254/) 잘못된 근거 선택 55%·누락 29%, [*PoT*](https://arxiv.org/abs/2211.12588) 입력값 연결 오류 47%)은 계산 자체보다 **값·단위·기간·연결/별도 매칭 오류**가 더 큰 병목임을 보여준다.
- **대응:** 구현·평가 시 **(a) 근거 선택 정확도 → (b) 값·단위·기간 추출 정확도 → (c) Python 비교 정확도**를 단계별로 분리 측정하고, 근거 검증 노드 프롬프트가 계산식뿐 아니라 *원문 셀과 추출된 숫자·단위·기간·대상의 일치 여부*를 중점 대조하도록 고도화한다.

### 4. [평가 후 판단] 재검색 0회 정책의 과도한 보류(`확인 불가`) 비율 확인
- **문제:** MVP에서 재검색을 0회로 고정하면 지연·비용 예측성은 높아지지만, 첫 검색에서 표 각주나 인접 페이지의 예외 조항이 빠졌을 때 보류(`확인 불가`)가 지나치게 많이 나올 수 있다.
- **대응:** 1차 평가셋 실행에서 **검색 누락으로 인한 `확인 불가` 비율**을 측정한 뒤, 실제 수치를 보고 제한적 1회 재검색 또는 표 주석·인접 블록 확장 도입 여부를 결정한다.

### 5. [백로그 + 프론트 TODO] 근거 조각 ID → 원문 구절·표 셀 바로가기 확장
- **문제:** 현재 MVP는 `chunk_id` 단위로 근거를 추적하므로 데이터 추적은 가능하지만, 확장 문맥이 길어질수록 사용자가 화면에서 정확한 원문 문장·표 셀을 한눈에 찾기 어렵다.
- **대응:** 백로그에 `quote`/`span`(문장 오프셋) 및 표 셀 위치 필드 확장을 등록하고, 프론트 TODO에도 **근거·판정 항목 클릭 시 해당 PDF 페이지의 정확한 문장·표 셀로 바로 스크롤 및 하이라이트 이동**하는 기능을 명시해 구현 방향으로 고정한다.

### 6. [단일 채팅 확정 · 평가 대상] 단일 채팅 AI 1회 라우팅의 경계 오분류 및 지연 관리
- **상황:** 사용 편의성을 위해 **단일 채팅 입력창**을 기본 UI로 확정했으므로 AI 1회 라우팅이 정석 구조다. 다만 *"이 보고서 매출 100억 넘는지 알려줘"*처럼 문서 QA와 기준 검토 경계에 걸친 표현은 AI가 오분류할 위험이 있다([*Anthropic*](https://www.anthropic.com/research/building-effective-agents), 2024; [*Larson 외*](https://aclanthology.org/D19-1131/), 2019).
- **대응:** 라우팅 평가셋으로 `T-01 / T-02 / T-03 / 미지원 / 명확화 필요` 분류 정확도와 지연을 측정한다. *(추후 API·CLI 테스트에서 `criteria_texts[]`가 별도 명시 전달되는 경로에만 코드 우선 분기 옵션을 고려한다.)*

### 7. [백로그 · 테스트] 채팅 원문 전달 시 복합 의도 혼합 및 인사말·출력 지시문 혼입
- **문제:** (a) *"보유기간을 알려주고 12개월 이하인지 검토해 줘"*처럼 **문서 QA + 기준 검토가 섞인 요청**은 요청당 1개 워크플로 제약 때문에 일부 의도가 빠질 수 있다([*NAACL 2019*](https://aclanthology.org/N19-1055/)). (b) 채팅 원문을 그대로 `criteria_texts: [question]`으로 넘길 때 *"안녕하세요 ~ 표로 정리해 주세요"* 같은 인사말·출력 형식 지시가 검토 조건으로 오인될 수 있다([*OWASP LLM01*](https://genai.owasp.org/llm2026/llm012026-prompt-injection/)).
- **대응:** MVP에서는 N-05가 인사말·출력 지시문을 검토 기준에서 제외하도록 프롬프트·테스트 항목에 추가하고, 다중 의도 분할은 후속 백로그로 관리한다.

### 8. [계약 반영] 라우팅 시점과 조회 시점 사이의 권한·버전 변경(TOCTOU)
- **문제:** N-10에서 권한과 문서 버전을 검사하더라도, 실제 검색·조회 시점에 권한이 철회되거나 버전이 바뀌면 잘못된 문서가 조회될 수 있다([*MITRE CWE-367*](https://cwe.mitre.org/data/definitions/367.html), [*OWASP API1*](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)).
- **대응:** N-10은 `요청 문서 ∩ 허용 범위`로 `document_scope`를 고정하고, N-01과 N-02에서도 조회 시점에 문서별 권한과 파싱 스냅샷 버전을 반드시 재검증한다. 권한 없는 요청자에게는 문서 존재 여부나 최신 버전을 노출하지 않는다.

### 9. [백로그 · 평가 대상] 결과 전달 노드 사후 재확인 생략 시 마지막 단계 요약 왜곡(Synthesis Drift)
- **문제:** MVP에서 N-11의 사후 재확인 장치를 생략하고 프롬프트 지침만 두기로 확정했다. 그러나 문헌([*FRANK*](https://aclanthology.org/2021.naacl-main.383/), NAACL 2021; *Cao 외*, 2024; [*Peters·Chin-Yee*](https://doi.org/10.1098/rsos.241776), Royal Society Open Science 2025)은 검증된 개별 항목을 자연어로 합치는 단계에서도 **원문에 없는 인과관계 연결("비용을 줄여 매출이 늘었다"), 수치 맥락 변경·임의 합산, 과잉 일반화**가 발생함을 보고한다.
- **대응:** 구조화 데이터(상태·항목·출처)는 Python이 원본에서 100% 직접 조립해 UI 정본으로 유지하고, 1차 평가셋에서 **N-11 요약 문장의 왜곡 발생률**을 별도 측정하며 **AI 요약 vs 정상 결과까지 정형 템플릿으로 렌더링하는 방식**을 비교 실험한다. 왜곡이 기준치를 넘으면 Python 경량 숫자·판정 대조 + 정형 템플릿 폴백(또는 전면 템플릿 전환)을 적용한다.

### 10. [계약 반영] 모순 탈락 원문·내부 오류의 API/스트리밍/내보내기 유출 방지 및 인용 과신 완화
- **문제:** 모순으로 탈락한 초안이나 내부 오류 상세를 화면 렌더링에서만 숨기면 API 응답·스트리밍·대화 내보내기로 그대로 노출될 수 있다([*OWASP API3*](https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/), [*CWE-209*](https://cwe.mitre.org/data/definitions/209.html)). 또한 사용자는 인용 링크를 잘 열지 않고 인용 배지의 존재만으로 답변을 과신하는 경향이 있다([*NN/G*](https://www.nngroup.com/articles/explainable-ai/), 2025).
- **대응:** N-11 서버 조립 단계에서 모순 탈락 원문과 내부 오류 상세를 응답 객체 자체에서 제거하고, `evidence_incomplete: true` 시 별도 알림(`evidence_notice`)을 강제하며, 프론트 TODO의 원문 문장·표 셀 바로가기로 검증 마찰을 낮춘다.

### 11. [백로그] 하네스 모델 실행 경계 — 문서 권한 검사와 외부 전송 차단의 분리
- **문제:** 제품 목표는 외부 전송 0건이고 개발 단계의 Ollama Cloud 사용은 공개 자료에 한정한다([모델 운용 방침](idea-backlog.md#01-모델-운용-방침-2026-11-24)). 그러나 문서 열람 권한 검사(N-10)는 "읽어도 되는가"만 판단하므로, 열람 권한이 있는 내부 보고서의 제목이나 민감 수치가 담긴 질문 원문이 라우팅(N-10)·요약(N-11) 등 모델 호출에서 클라우드로 전송되는 것을 막지 못한다(EGM Stage 5 Blocker).
- **대응:** MVP 계약에는 아직 넣지 않고 백로그로 관리한다. 후속으로 하네스 단일 모델 어댑터(`origin/JM:rag/llm/ollama_client.py` 전송 계층 재사용)에서 **제품 프로필은 외부 인터넷 송신 차단(승인된 사내 AI API·사내 백업 저장소만 Allowlist 허용)**, **개발 클라우드 프로필은 질문·제목·기준·근거 페이로드 전체가 공개 자료로 표시·검증된 경우에만 허용**하도록 강제한다([아이디어 백로그 4.11](idea-backlog.md#411-하네스-모델-실행-경계--로컬-전용-강제-및-개발-클라우드-공개-자료-검증-정책-2026-11-28)).
- **운영 전제 (2026-11-28 확정):** 제품 프로필에서 허용하는 엔드포인트는 **승인된 사내망 중앙 Ollama 서버(추후 OpenAI 호환 API 확장 가능)와 사내 백업 저장소뿐**이며(사설 CA TLS, OS 키체인 키), 외부 인터넷 송신은 0건으로 차단한다. MVP 1차는 `Ollama` 호출 방식으로 확정했으므로 JM의 기존 Ollama 클라이언트는 살리고, 코드에 고정된 주소(특히 NW `ollama.com` 직접 호출)는 설정으로 분리해 단일 AI 연결 모듈(허용 주소 목록 강제)을 거치게 한다([배포 아키텍처 §6](local-daemon-and-deployment.md#6-보안운영-체크포인트)).

### 12. [계약 반영] 확장 문맥 출처 · 기준 원문 충실도 · `outcome` 매핑
- **문제:** (a) N-02의 `source_refs[]`는 원래 검색 범위만 가리키는데 N-03은 확장 문맥(`context_text`) 전체로 판정하므로, 인접 블록(다음 쪽 각주 등)으로 지지된 주장이 근거가 없는 원래 블록만 인용할 수 있다. (b) N-05/N-06이 기준의 연산자·임계값을 바꿔도(예: "이하" → "이상") N-03은 생성된 주장과 근거만 대조해 잘못된 판정을 통과시킬 수 있다. (c) T-02의 `unsupported_structure`·`needs_clarification`(검색도 하지 않은 결과)이 확인 항목 0건 규칙 때문에 "근거 부족"으로 표시될 수 있다.
- **대응 (2026-11-28 계약 수정):** (a) N-02가 `expanded_source_refs[]`를 별도 보존하고, `evidence_refs[]`(`chunk_id`)는 두 출처 목록을 함께 가리키도록 N-03이 해석하며, N-11이 둘을 함께 표시한다. (b) T-02가 `original_criterion`(`original_text` + `conditions[]`)을 N-03에 넘기고, 원문 기준과 어긋나면 `insufficient` → `unverifiable`로 하향한다. (c) N-11이 `status`·`outcome`을 확인 항목 개수보다 먼저 보는 [결정적 매핑 표](small-nodes/N-11.md#32-워크플로-결과--사용자-상태-결정적-매핑-2026-11-28)를 적용한다.

### 13. [백로그] 기준 검토 일괄 검증 구조의 예산 소진 위험
- **문제:** T-02는 모든 처리 가능 기준의 `N-01 → N-02 → N-06` 루프가 끝난 뒤 N-03을 일괄 실행한다. 기준 목록이 길면 검증 시작 전에 요청 시간·토큰 예산이 소진되어, 판정 초안은 있어도 검증 완료 결과가 0건이 될 수 있다.
- **대응:** MVP 그래프는 유지하고 후속으로 요청 전체 예산과 결과 조립·N-11 예비 시간을 예약한 뒤 **기준 1건 또는 소배치 단위로 `N-01 → N-02 → N-06 → N-03`을 완료**하고, 예산 소진 시 검증이 끝난 기준만 반환하며 미평가 기준을 별도 표시하는 방식을 검토한다([아이디어 백로그 4.12](idea-backlog.md#412-t-02-후속-개선--기준별소배치-검증-파이프라인-및-예산-소진-시-부분-완료-반환-2026-11-28)).
