## 1. 처음 기획 (10/25 최종본)

### 1.1 문제와 목표
- **문제:** 보고서 검토에 시간이 오래 걸리고, 외부 AI에 문서를 올리면 유출 위험이 있다.
- **개념:** 사용자가 정한 기준으로 보고서를 점검하는 **로컬 에이전트**.
- **3대 기능:** Report Structuring / Search for Evidence / Verification-based Feedback.

### 1.2 처리 흐름 (PPT)
1. **보고서 처리:** PyMuPDF로 텍스트·해시·페이지·좌표 추출 → 필요한 곳에만 VLM → 구조 검증·교차 확인 → 안정 ID 부여 → BM25+Dense 색인·SQLite 저장.
2. **질의 처리:** 질문·기준 입력 → 질의 분석·분해 → BM25+임베딩+Rerank 검색 → 생성 전 검증(Python 계산) → 피드백 → 주장-근거 검증 → 결과 표시.
3. **재검색:** 최대 2회. 사용자가 수정하면 이력을 관리한다.

### 1.3 기술 스택 (PPT)
| 계층 | 기획 |
|---|---|
| UI | Chrome Extension MV3 |
| 로컬 서버 | FastAPI · Python · Ollama |
| 문서 처리 | Qwen3-VL · PyMuPDF · Pydantic |
| 검색 | BM25 · BGE-M3 · bge-reranker-v2-m3 |
| 에이전트·검증 | LangGraph · Python 계산 · 주장-근거 검사 |
| 저장 | FAISS · SQLite · JSONL |

### 1.4 정량 목표 (계획서)
| 지표 | 목표 |
|---|---|
| 구조화 micro F1 | ≥ 0.85 |
| 검색 Recall@5 | ≥ 0.85 |
| 인용 정확도 | ≥ 95% |
| 보류(abstention) F1 | ≥ 0.85 |
| 외부 전송 | 0건 |

- **평가셋:** 공개 국문 보고서 6–10종(KISTEP 2024 연차보고서, 2023 R&D 조사 등), 영역 50개 이상, 질의 60개 이상. 최종은 영역 20개, 질의 30개.
- **베이스라인:** PyMuPDF → 문단 분할 → BGE-M3 → Qwen3-VL-4B. 전처리는 PyMuPDF / Docling / 선택적 VLM을 비교한다.

### 1.5 역할 (계획서)

| 이정민 | 문서 처리·VLM |
| 김상엽 | 검색·근거 색인 (BM25/임베딩) |

| 김나원 | 사용자 화면·로컬 API (Chrome Extension, FastAPI) |

## 4. 남은 과제 (14–16주차 후보)

1. **연결**
   - NW 결과 → JM 청킹·색인: 청킹·승인 조건을 합의해야 한다.
   - JM 워크플로 → 로컬 API(FastAPI) → SY 사이드 패널.
2. **검색:** Dense(BGE-M3) + RRF를 붙이고 Reranker를 구현한다(결정 #9). Reranker 모델은 실험으로 고른다.
3. **평가:** 평가셋을 구축하고 Recall@5·인용 정확도·보류 F1을 측정한다.

5. **미정 결정 (#4–8):** 데이터 계약, 저장소, 실행 정책, 수정·생성 계약, 평가 체계.
